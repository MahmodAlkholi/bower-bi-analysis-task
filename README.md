# لوحة المبيعات — Power BI Project (PBIP)

لوحة تحكم كاملة مبنية على ملف البيانات (`ملف البيانات.xlsx`) باستخدام **Power BI Project (PBIP)** —
مشروع Power BI حقيقي يفتح مباشرة في **Power BI Desktop**، وليس صورة أو قالباً.

---

## 1. كيف تفتح المشروع

1. ثبّت **Power BI Desktop** (الإصدار 2024 أو أحدث — PBIR مدعوم في الإصدارات الحديثة).
2. افتح الملف:
   ```
   PowerBI_SalesDashboard.pbip
   ```
   أو افتح مجلد المشروع في Power BI Desktop ثم اختر `PowerBI_SalesDashboard.Report\definition.pbir`.
3. عند أول فتح سيقوم Power BI Desktop بتحميل البيانات من النموذج (البيانات **مدمجة داخل** النموذج
   كـ Base64 — لا يوجد أي مسار ملف يحتاج تعديلاً، والمشروع يعمل على أي جهاز).
4. من الشريط: `File → Save as` لحفظه كملف `.pbix` إذا أردت.

> **لا يوجد أي إعداد مطلوب.** لا مسارات، لا صلاحيات، لا اعتماد على ملفات خارجية.

## 3. صفحات التقرير

| الصفحة | المحتوى |
|---|---|
| **نظرة عامة** | 5 بطاقات KPI (إجمالي المبيعات، الأرباح، هامش الربح، عدد الطلبات، متوسط قيمة الطلب) + خط شهري (المبيعات والأرباح) + أعمدة حسب المدينة + 3 شرائح (السنة والشهر / المدينة / المنتج) |
| **تحليل المنتجات** | شرائح الفئة + أعمدة مزدوجة (المبيعات والأرباح) لكل منتج + هامش الربح + جدول تفصيلي |
| **تحليل المدن** | المبيعات والأرباح لكل مدينة + خط شهري لكل مدينة (legend) + جدول تفصيلي |
| **جودة البيانات والتسعير** | الطلبات حسب حالة التسعير + متوسط معامل التسعير شهرياً + مقارنة القيمة الاسمية بالمبيعات + جدول كل الطلبات |

كل الرسوم البيانية مرتبطة بصفحة **نظرة عامة** والشرائح تعمل عبر كل الصفحات (تحديد متقاطع).

## 4. النموذج الدلالي (Star Schema)

| الجدول | النوع | الوصف |
|---|---|---|
| `المبيعات` | Fact | 421 طلباً — أرقام الطلبات والتاريخ والمنتج والمدينة والكمية والسعر والمبيعات والأرباح + الأعمدة المحسوبة `القيمة الاسمية`، `معامل التسعير`، `حالة التسعير` |
| `التاريخ` | Dimension | 366 يوماً مستمراً (2023-01-01 → 2024-01-01) + هرمية `التسلسل الزمني` (سنة → ربع → شهر → يوم) + مُعلَّمة كـ Date Table |
| `المنتجات` | Dimension | 10 منتجات + `الفئة` |
| `المدن` | Dimension | 6 مدن + `المحافظة` |
| `المقاييس` | Measures | 17 مقياس DAX |

**العلاقات:** `المبيعات.تاريخ الطلب` → `التاريخ.تاريخ الطلب`، `المبيعات.المنتج` → `المنتجات.المنتج`،
`المبيعات.المدينة` → `المدن.المدينة` (اتجاه تصفية واحد من البُعد إلى Fact).

### المقاييس (17)

| المجموعة | المقياس | الوصف |
|---|---|---|
| المبيعات | `عدد الطلبات` | COUNTROWS |
| | `إجمالي المبيعات` | SUM(إجمالي المبيعات) |
| | `إجمالي الأرباح` | SUM(الأرباح) |
| | `هامش الربح` | DIVIDE(الأرباح، المبيعات) |
| | `إجمالي الكمية` | SUM(الكمية) |
| | `متوسط قيمة الطلب` | المبيعات ÷ الطلبات |
| | `متوسط سعر الوحدة` | المبيعات ÷ الكمية |
| التسعير | `القيمة الاسمية الإجمالية` | SUMX(الكمية × سعر الوحدة) |
| | `فارق التسعير` | القيمة الاسمية − المبيعات |
| | `نسبة التسعير` | المبيعات ÷ القيمة الاسمية |
| | `متوسط معامل التسعير` | AVERAGE(معامل التسعير) |
| | `عدد طلبات الخصم` | CALCULATE + فلتر حالة التسعير |
| | `مبيعات الخصم` | CALCULATE + فلتر حالة التسعير |
| التغطية | `عدد المنتجات` / `عدد المدن` | DISTINCTCOUNT |
| النمو | `نمو المبيعات` / `نمو الأرباح` | DATEADD على جدول التاريخ |

## 5. قواعد تنظيف البيانات (مطبَّقة وموثّقة)

| القاعدة | التفصيل |
|---|---|
| مسافات زائدة | `strip()` على أسماء المنتجات والمدن (السطر `1421` كان يحتوي `'بخاخة '` و`'بنها '`) |
| خطأ مطبعي | `'بخاخة'` ← `'بخاخ معطر'` (السطر الوحيد المطابق لمنتج به 38 صفاً) |
| تواريخ | تحليل `YYYY-MM-DD` — كل السطور الـ 421 صالحة |
| أرقام | الكمية `Int64`، السعر/المبيعات/الأرباح `Double` (بدون أي تقريب على القيم الأصلية) |
| لا حذف | لم يُحذف أي صف. المجموع = 421 طلباً = عدد صفوف الملف الأصلي |

### أعمدة مشتقّة (محسوبة في المعالجة، موثّقة في `tools/build_pbi_project.py`)

- `القيمة الاسمية` = `الكمية × سعر الوحدة`
- `معامل التسعير` = `إجمالي المبيعات ÷ القيمة الاسمية`
- `حالة التسعير` = `خصم` (< 0.999) / `سعر عادي` / `زيادة` (> 1.001)
- `الفئة` (تصنيف مشتق للمنتجات) و `المحافظة` (للمدن)

> `الفئة` و `المحافظة` تصنيفان مُضافان للتحليل ولم يكونا في الملف الأصلي — يمكن تعديلهما أو حذفهما
> من `PRODUCT_CATEGORY` / `CITY_GOVERNORATE` داخل `tools/build_pbi_project.py`.

## 6. ⚠️ ملاحظة مهمة: أنماط التسعير في البيانات

`إجمالي المبيعات` **لا يساوي دائماً** `الكمية × سعر الوحدة`. الفحص على كل الـ 421 صفاً:

| الشهر | عدد الطلبات | معامل التسعير | القراءة |
|---|---|---|---|
| **2023-08** (أغسطس) | 44 | **0.45** | كل طلبات أغسطس بسعر 45% من القيمة الاسمية (خصم 55%) |
| **2023-03** (مارس) | 36 | **1.35** | كل طلبات مارس بسعر 135% من القيمة الاسمية (زيادة 35%) |
| باقي الشهور | 341 | 1.00 | تسعير عادي |

**هذه أنماط شهرية منتظمة وليست أخطاء عشوائية** — كل طلبات الشهرين متسقة مع معامل واحد، ولا يوجد
استثناء واحد. الأمر الغريب الوحيد: طلب `2024-01-01` وحيد (153.4) خارج النمط.

لم يُصحَّح أي شيء — تم توثيق النمط وإتاحته في صفحة **جودة البيانات والتسعير** حتى تقرر أنت:
هل هو حملة تسعير فعلية، أم خطأ في إدخال البيانات لتلك الشهور، أم تعديل أسعار (بضريبة/عمولة مثلاً)؟

## 8. تحديث البيانات من ملف جديد

```bash
python tools/build_pbi_project.py --source "الملف الجديد.xlsx" --scope all
```

- `--scope data` (الافتراضي): يحدّث `data/*.csv` و `model.bim` فقط — **ولا يمس** التقرير، فإذا كنت
  عدّلت التقرير في Power BI Desktop فلن تفقد تعديلاتك.
- `--scope all`: يولّد المشروع كاملاً (البيانات + النموذج + التقرير + المعاينة).

المتطلبات: Python 3.9+ مع `pandas` و `openpyxl`.

> **ملاحظة:** البيانات مدمجة داخل النموذج كـ Base64 لتسهيل النقل (افتح المشروع على أي جهاز مباشرة).
> لو فضّلت مصدراً ملفياً حياً، استبدل خطوة `Binary.FromText(...)` داخل `model.bim` بـ
> `Csv.Document(File.Contents("C:\\...\\data\\sales.csv"), ...)` لكل جدول.

## 9. النشر إلى Power BI Service

1. في Power BI Desktop: `File → Publish` (أو `Publish to existing workspace`).
2. اختر مساحة العمل، وأشر إلى مجلد `PowerBI_SalesDashboard.SemanticModel` كـ Dataflow/Model.
3. عند النشر، اختر `Publish to existing workspace` ثم اربط التقرير بالنموذج المنشور.

## 10. الفحص والتحقق

```bash
python tools/validate_project.py
```

يفحص المشروع مقابل مخططات JSON الرسمية من Microsoft
(`visualContainer`, `report`, `page`, `pagesMetadata`, `versionMetadata`, `definitionProperties`,
`platformProperties`, `pbipProperties`) ويتحقق أن كل مرجع في التقرير (جدول/عمود/مقياس) موجود فعلاً
في النموذج، وأن بيانات Base64 سليمة غير مشوّهة.

**نتيجة آخر فحص:** 40 ملف — 0 أخطاء مخطط · 0 مراجع مكسورة · البيانات المدمجة سليمة.

كما تم تشغيل مدقّق `pbir` الرسمي (من مطوّري PBIR) على التقرير:
`Valid (3 warnings)` — التحذيرات الثلاثة كلها من نوع `TOO_MANY_FIELDS` على الجداول التفصيلية
(7 و5 و11 عموداً)، وهي توصيات تصميمية لا أخطاء.
